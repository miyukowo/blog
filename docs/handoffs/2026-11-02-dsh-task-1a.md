## Interfaces and behavior

Export captureSite({ distDir, sourceDir, sourceRevision }) and assertSiteContract(actual, baseline, { allowedChanges }).

captureSite returns schemaVersion 1 using the checked-in baseline's structure:

- Tracked source-content paths, SHA-256 file/body hashes; take the protected path list from the baseline supplied by the caller rather than discovering Git state.
- HTML public paths, canonical URL, language, robots, OG image and hreflang destinations.
- RSS language/item links, sitemap URLs, generated OG paths and search output/language evidence.

Accept the baseline explicitly in capture options when its protected path list is required; keep that option and the CLI documented in the file. Take sourceRevision as a caller-provided identifier; do not invoke Git.

CLI:

    node scripts/site-contract.mjs capture --dist <dist> --source <source> --baseline <baseline.json> --source-revision <revision> --output <output.json>
    node scripts/site-contract.mjs assert --actual <actual.json> --baseline <baseline.json>

Capture must parse actual output and hash actual content. Use a real existing HTML/XML parser; do not implement general HTML parsing with regex. Resolve index.html to its public directory path and 404.html to /404.html. Handle XML namespaces and URI-encoded taxonomy paths deliberately.

Assertions must fail nonzero with the affected path and field for missing/changed protected URLs, canonical/language/translation identity, lost content, changed body hash or duplicate route. Added legitimate posts can be explicitly classified; silently ignoring arbitrary new/changed routes is not acceptable.

Known baseline defect allowance is narrow: /vi/rss.xml may change language from en-us to vi-vn, without allowing arbitrary other feed/URL changes. Metadata/source-revision timestamps are evidence, not required byte equality between captures. Unclassified changes fail.

## Acceptance criteria and tests

Write meaningful failing tests first, observe the failure, then implement. Include:

1. A fixture directory captured from HTML/XML/source files yields the expected root/post/VI category URLs, metadata, feed entries and body hashes.
2. Removing an existing post route fails with that path.
3. Adding /index to a folder post URL fails.
4. Replacing /vi/categories/huong-dan/ with a Unicode slug fails.
5. Changed canonical, reciprocal translation destination, source body or duplicate route each fails with the affected field.
6. A legitimate added translated post pair passes only when explicitly classified.
7. The VI RSS language correction passes only under its narrow allowance; an unrelated feed-item change still fails.
8. CLI capture/assert operate on temporary fixtures and return useful nonzero failures. Tests never write dist, content or fixtures in the real project.
9. Source capture uses the supplied protected paths and revision without reading .git.

Do not add placeholder tests or weaken assertions to pass the baseline. Do not build the application for this subtask; full runtime/build wiring is Task 1b after this interface has been reviewed.
